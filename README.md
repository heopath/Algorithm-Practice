## 하루 루틴

1. 새 문제를 최대 1개 골라 입력·출력, 제한 조건, 작은 예제를 정리합니다.
2. 30~40분 동안 직접 접근합니다. 막히면 AI나 해설에서 필요한 힌트부터 확인합니다.
3. 도움을 받았다면 자료를 닫고 처음부터 다시 구현합니다.
4. 직접 제출해 통과한 코드를 주차 폴더에 넣고 진행표를 체크합니다.
5. 접근법·자료구조 선택 이유·시간복잡도·경계 사례를 짧게 기록합니다.
6. 3일 뒤와 7일 뒤 다시 풀어 보고 도움 없이 풀었는지 남깁니다.

하루 60~90분을 시작 기준으로 잡고, 면접이 가까우면 복습만 해도 됩니다. 풀지 못한 날은 실제로 시도한 내용이 있을 때 기록합니다. 커밋 수를 채우기 위한 기록은 필요하지 않습니다.

## AI·해설 사용 원칙

- 처음부터 완성 코드를 받기보다 접근 방향과 막힌 부분의 힌트를 요청합니다.
- 도움을 받은 범위를 솔직하게 적습니다.
- 같은 날 재구현과 며칠 뒤 재풀이는 구분합니다.
- 예제 통과 외에도 중복 값, 최소 입력, 큰 수 등의 경계 사례를 확인합니다.
- 실제 채용 시험에서는 해당 기업의 도구 사용 규정을 따릅니다.

## 풀이 파일

파일명 예시: `PGS_42576_완주하지못한선수.java`

```text
solutions/
├── week1-basic/
├── week2-datastructure/
├── week3-bfs-dfs/
└── week4-greedy-dp/
```

4주차 폴더 이름은 기존 경로를 유지합니다. 초기 과정은 탐욕법·문자열·복습 중심이며 DP와 이분탐색은 후속 학습에 포함합니다.

프로그래머스의 `class Solution` 풀이들은 문제별로 독립 실행합니다. 여러 파일을 한 번에 컴파일하면 같은 클래스 이름이 충돌할 수 있습니다. 문제 전문 대신 원문 링크와 본인의 풀이 설명을 남깁니다.
